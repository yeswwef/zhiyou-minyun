# 源码阅读导航

本轮为自有代码补充说明，不改变业务逻辑。文件顶部的 `@module-note` 说明模块位置和职责；函数上方说明用途、接口协作及关键数据库调用。原有有效注释保留。匿名的 map、事件和 Promise 回调结合所在函数阅读，不逐行重复注释。

## 建议阅读顺序

1. `app/layout.tsx`、`app/page.tsx`：全局页面框架及首页跳转。
2. `app/(c)`、`app/b`、`app/admin`：分别是游客、商户和后台页面。路由组 `(c)` 不出现在浏览器 URL 中。
3. `features`、`components`：功能模块和共用界面。页面入口短是因为把复杂交互委托给这些组件。
4. `app/api`：前端请求进入后端的入口，按 GET、POST、PATCH 等方法执行处理。
5. `lib/auth.ts`、`lib/roles.ts`、`lib/db.ts`：会话、角色守卫、数据库访问基础。
6. `prisma/schema.prisma`：数据库实体与关联；再结合业务接口阅读事务和筛选条件。

## AI 问答链路

`app/(c)/ask/page.tsx` 读取网址初始问题 → `features/ai-chat/AskExperience.tsx` 管理输入与会话 → `app/api/chat/answer/route.ts` 校验请求并读取历史 → `features/rag/pipeline.ts` 执行问答。

RAG 内部：context 还原单个主问题的指代；store 加载本地索引；retrieve 进行 BM25、向量、RRF 和重排；providers 负责外部模型接口；pipeline 编排证据审查、生成、验证及补充建议。stream 处理 SSE 分片，logger 绑定请求日志，limits/http 控制请求资源。资料索引在 `.data/rag/index.json`，不是聊天历史表。

回答返回页面后，presentation 整理段落，AnswerContent 安全渲染加粗标题和列表。状态提示是实际处理阶段，不是输出模型内部思维过程。

## 票务与缓存链路

后台维护场馆、项目和时段；游客查询票务目录并提交预约，后台核销。`features/tickets/resilience.ts` 通过随机TTL、负缓存、并发请求合并和Redis锁降低回源压力。Redis不可用有进程内降级，但这不等于分布式保证仍然存在。

预约接口 `app/api/bookings/route.ts` 先校验游客身份，再按用户/IP/时段限流，通过有界队列进入数据库事务。容量条件更新与预约创建同事务完成，缓存不能决定是否有票。

## 商城与体验课程

`app/b` 是实体商户工作台，`app/api/merchant` 处理商品、订单、作品和课程。`features/merchant/data.ts` 转换数据库记录为DTO；游客与商户订单视图分开。金额以整数分保存，展示转换为元。当前支付是业务模拟，不是第三方真实支付。

## 社区与文旅资源

社区页面与 `features/community/components` 管理发布、编辑、点赞、评论、关注。validation 校验表单，storage/community 写入与删除上传图片，data 组装帖子DTO。接口中应关注作者/当前用户过滤以及文件操作和数据库更新的先后关系。

文旅资源展示在 `app/(c)/resources`，资源卡片及收藏、加入行程位于 `features/destination-resources/components`。repositories/services/hooks 中部分文件目前是导出占位，不表示对应分层服务已经全部实现。

## 身份与数据安全

密码采用带盐哈希，会话使用签名Cookie。后端必须验证角色和数据归属，不能只相信前端隐藏了按钮。`use client` 文件可以处理交互，但不可放入密钥。调试日志不能输出环境变量、密码或完整凭据。
