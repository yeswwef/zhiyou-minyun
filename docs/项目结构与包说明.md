## 一、顶层目录：一眼看懂

```
zhiyou-minyun/
├─ app/              ← 页面和接口（Next.js 的 App Router，一切从这开始）
├─ lib/              ← 公共代码（数据库连接等，不放在 app 里）
├─ prisma/           ← 数据库模型定义 + 迁移记录
├─ public/           ← 静态文件（图片、图标，浏览器直接访问）
├─ docs/             ← 项目文档（本文件 + 启动说明）
├─ .vscode/          ← VS Code 配置（任务、调试、推荐扩展）
├─ generated/        ← Prisma 自动生成的客户端代码（不要手改，可删可重建）
├─ .next/            ← Next.js 构建产物（自动生成，不要手改）
├─ node_modules/     ← 第三方依赖（自动生成，不要手改）
├─ .env              ← 本地环境变量（含数据库密码，**不进 git**）
├─ .env.example      ← 环境变量模板（给队友复制用，进 git）
├─ prisma7.config.ts ← Prisma 7 的配置文件（连接串、迁移、seed 都写这里）
├─ docker-compose.yml← 一条命令起 Qdrant 向量库容器
├─ package.json      ← 依赖清单 + npm 脚本（`npm run xxx` 都在这定义）
└─ tsconfig.json     ← TypeScript 配置（含 `@/*` 路径别名）
```

## 二、`app/` 目录（最核心）

Next.js 用**文件路径当 URL**，所以目录结构 = 网站结构。

```
app/
├─ layout.tsx           根布局：所有页面最外层的外壳（<html><body> 级）
├─ page.tsx             首页 → 对应 URL  /        （当前是入口页：C 端 / B 端两个链接）
├─ globals.css          全局样式：Tailwind 入口 + .card/.btn/.input 这些自定义类
├─ favicon.ico          网站图标
│
├─ (c)/                 【路由组】括号目录**不出现在 URL 里**
│  ├─ layout.tsx        C 端专用外壳（以后放底部导航）
│  └─ home/page.tsx     C 端首页 → URL /home
│
├─ b/                   普通目录，**出现在 URL 里**
│  ├─ layout.tsx        B 端后台外壳（以后放登录鉴权、侧边菜单）
│  └─ dashboard/
│     └─ page.tsx       B 端看板 → URL /b/dashboard
│
└─ api/                 【接口目录】里面的 route.ts 不是页面，是后端接口
   └─ health/
      └─ route.ts       GET /api/health  → 返回数据库是否连通、几张表各有多少行
```

**要记住的三条规矩**

1. **`page.tsx` = 页面**：一个目录里放了 `page.tsx`，这个路径才能被访问。
2. **`route.ts` = 接口**：放在 `app/api/` 下，前端用 `fetch("/api/xxx")` 调用；同一个文件里导出 `GET` / `POST` 等函数表示对应 HTTP 方法。
3. **`layout.tsx` = 外壳**：同级以及子级所有页面都会被它包住（导航栏、页头这类公共部分放这里）。

> 关于 `(c)` 这种括号：叫「路由组」，**只是用来分组，不进 URL**。
> 所以 `app/(c)/home/page.tsx` 的地址是 `/home`，不是 `/c/home`。
> 而 `app/b/dashboard/page.tsx` 是普通目录，地址就是 `/b/dashboard`。

## 三、`lib/` 目录

放**不属于页面、以后会被多处复用**的代码。当前只有一个：

| 文件 | 作用 |
| --- | --- |
| `lib/db.ts` | 创建并导出 Prisma 数据库客户端（`prisma`）。全项目统一从 `@/lib/db` 引入，避免重复建连接。里面用 `@prisma/adapter-mariadb` 是因为 **Prisma 7 起必须通过 driver adapter 连库**。 |

以后会往里放什么（等你说要了再加）：`lib/auth.ts`（登录鉴权）、`lib/http.ts`（统一接口返回格式）、`lib/rag.ts`（检索问答）、`lib/ai/`（模型调用封装）。

## 四、`prisma/` 目录

| 文件 | 作用 |
| --- | --- |
| `prisma/schema.prisma` | **数据库模型的唯一事实来源**。现在只有 4 组核心表：账号（User）、文旅资源（Resource / Tag / ResourceTag）、收藏（Favorite）、问答历史（ChatSession / ChatMessage）。 |
| `prisma/migrations/` | 每次 `npm run db:migrate` 生成的迁移记录（SQL），**要进 git**，队友拉到后用 `npm run db:migrate` 就能同步出同样的表。 |

**改表的标准流程**（很重要，记住这三步）：

```powershell
# 1. 改 prisma/schema.prisma
# 2. 生成并应用迁移
npm run db:migrate -- --name 加了一张表
# 3. 重新生成客户端（migrate 通常会自动做，保险起见再跑一次）
npm run db:generate
```

## 六、npm 依赖包：每个是干什么的

### 运行时依赖（`dependencies`）

| 包 | 作用 | 为什么现在就有 |
| --- | --- | --- |
| `next` | 框架本体：既是前端（React 页面），也能写后端（`app/api` 接口） | 项目地基 |
| `react` / `react-dom` | 页面 UI 库，Next.js 底层就是 React | Next 的必需伴生包 |
| `@prisma/client` | 在代码里操作数据库的客户端（`prisma.resource.findMany()` 这种写法） | 数据层 |
| `@prisma/adapter-mariadb` | MySQL 驱动适配器。**Prisma 7 起必须用它才能连 MySQL**，否则客户端起不来 | Prisma 7 的硬要求 |

### 开发依赖（`devDependencies`）

| 包 | 作用 |
| --- | --- |
| `prisma` | 命令行工具：`prisma migrate` / `prisma generate` / `prisma studio` 都靠它 |
| `tsx` | 直接运行 `.ts` 脚本（以后写 seed / 批处理脚本用），当前留着备用 |
| `dotenv` | 让 `prisma7.config.ts` 能读到 `.env` 里的连接串 |
| `typescript` | TypeScript 编译器（`npm run typecheck` 用它） |
| `tailwindcss` + `@tailwindcss/postcss` | 原子化 CSS 框架，`className="p-4 rounded-xl"` 这类写法靠它 |
| `eslint` + `eslint-config-next` | 代码规范检查（`npm run lint`） |
| `@types/node` `@types/react` `@types/react-dom` | TypeScript 的类型声明，让编辑器有提示、编译不报错 |

> **已经卸掉的两个**：`openai`（模型调用）和 `@qdrant/js-client-rest`（向量库客户端）。
> 它们属于「RAG 问答」那一步，等你做到再接——见归档版本里的写法。
